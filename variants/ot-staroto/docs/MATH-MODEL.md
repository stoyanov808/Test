# ОТ СТАРОТО: the v3 mathematical model

The offered modes have **96.5% theoretical expected return**, measured against the amount actually debited, at every supported stake: €0.10, €0.20, €0.50, €1, €2, €5, €10 and €20. This comes from complete integer-cent outcomes and exact rational weights, rather than assuming a small simulation establishes RTP. It is an independent virtual-credit prototype and has no third-party gambling certification.

RTP describes an expectation over many independent paid rounds. An individual round, a player's session or a finite test can return less than 96%, including zero. The game never adjusts odds using wallet size, losses, history or a target payout balance.

## Outcomes and selection

The frozen [catalogue](../src/math-model.json) contains **47,104 complete round entries** in ten pools. Its builder evaluates every entry at all eight stakes: **376,832 complete stake outcomes**. Entries are compact procedural seeds and verified cent payouts; the actual full cascades, character shots, sparse coin waves, collectors, retriggers and bonus upgrades are regenerated by the engine. Awards come from the visible mechanic receipts. There is no added floor award, missing-payout top-up or hidden settlement multiplier.

Each pool gives every entry positive integer ticket weight. Calibration increases the weight of an ensemble whose average falls on the other side of the target expectation. The exact weighted sum then equals the target. The strongest individual full outcome is below 0.25% of its conditional pool; this limit prevents one repeat sequence from carrying a large share of the game. Pool diversity, effective outcome counts, win/cap probabilities and bonus-tier fractions are recorded in [the proof](mathematics-proof.json).

Production selects tickets from independent `crypto.getRandomValues` uint32 words using integer rejection sampling. Rejected modulo-tail words are discarded; large ticket totals use multiple words. The complete consumed entropy tape is recorded in the round. Reload validates and replays that tape, checks the catalogue index, seed, full mechanic receipt, cent award and ledger chain, and consumes no new random word. An entropy failure or catalogue mismatch throws before credits are debited.

`playFixtureRound` is a deterministic QA factory for engine tests and the development-only browser reset hook. Production uses `playRound` and Web Crypto. The raw `simulateRound` factory is for building and independently checking procedural outcomes.

This is a finite outcome catalogue. Its entries remain repeatable, and it does not offer an unlimited set of possible procedural seeds. The complete catalogue and weights are public so that limitation can be assessed directly.

## Base play and the 3× XBet

Base play has a **1/200** natural bonus-entry probability. The 3× XBet has **1/40**, exactly five times the probability for the whole bonus entry event. This is not a fivefold per-scatter draw rate. Both modes use precisely the same two conditional pools: ordinary rounds and natural bonus rounds. Natural entries contain three, four, five or six visible scatters in random distinct reels and rows, and start their corresponding bonus. Every scatter tier has nonzero weight.

Let `A` be the expected ordinary-round award and `B` the expected full natural-bonus round award, in base-bet multiples. Exact pool calibration gives:

- `A = 193/400 = 0.4825`
- `B = 38793/400 = 96.9825`

Base return is `(199 A + B)/200 = 193/200 = 96.5%`.

XBet costs three bets, so its return is `(39 A + B)/(40 × 3) = 193/200 = 96.5%`.

The XBet raises entry probability while preserving the conditional game and bonus distributions. It does not secretly strengthen symbols, alter a bonus after entry or change the cap.

## Feature entries, purchased bonuses and God

The three guaranteed-character entries, four purchased bonuses and God each have their own weighted full-round pool. For each mode and stake, the proof verifies:

`sum(weight × payoutCents) × 200 = sum(weight) × costCents × 193`.

Purchased-bonus prices remain 95× / 150× / 1,800× / 2,500×. Feature entries cost 8.5× / 2.7× / 25×; these are separate from the 3× bonus-chance XBet. God costs 3,000× and its one actual MAX symbol awards the 19,999× cap only when a recorded shot hits it. God misses settle the same board. Its weighted shooting outcomes supersede the earlier procedural `4.32/30` hit-probability formula; its exact expected return also equals 96.5% against the 3,000× debit.

## Changing and checking the model

Source hashes pin the catalogue to its procedural engine, types, model schema and builder. Development startup and production builds run a guard that rejects stale sources, inconsistent model/proof hashes, missing modes, invalid stake payouts or failed rational expectations. The selected runtime outcome is also regenerated and compared with its verified payout before any debit.

After intentionally changing mathematical rules:

```sh
npm run math:build
npm run math:check
npm run math:check:full
npm test
```

The full check independently regenerates all 376,832 stake outcomes and verifies payouts, cap, trigger branch and mechanic ledgers. [The simulation](mathematics-sample.json) additionally exercises real production crypto selections and reports observed variation; its observed percentage is not substituted for the exact model proof.
